# Outstanding work (updated 2026-10-12)

The working tree is `rustuya-local 0.1.0.dev7`, requiring `tuya-interpreter>=0.1.0a2` and `pyrustuyabridge>=0.4`.
HA integration and manager plugin tests use `rustuya-manager>=0.2.2`. The Sans-I/O Rust driver handles conversion;
the registry, IL MQTT adapter, transports, timers and rule loading moved to `rustuya_local.host`.
Release changes are in [CHANGELOG.md](../../CHANGELOG.md). This document does not verify current deployed-server state.

After the 2026-10-11 review, concurrent device-settings saves were serialized and Hub rule-pack and Runner reconnect
cleanup were strengthened. Atomic replacement and task cleanup were shared, and watched device reads moved off the
event loop. Real-device validation remains limited to M2 below; code review and automated tests do not complete it.

The completed milestones below preserve the earlier history. The recorded deployment baseline was tuya2ildevice
0.3.16, rustuya-local 0.0.45, rustuya-manager 0.2.1 and pyrustuyabridge 0.4.0. rustuya-homeassistant received a retirement
notice but was not archived. On 2026-09-27 the repository was renamed to rustuya-homeassistant and reverted the same day:
it is not HA-only, and multiple names are confusing. Repository, PyPI, CLI and plugin identity remain `rustuya-local`
(the Python import is `rustuya_local`). Repository abbreviations: **T** tuya2ildevice, **L** rustuya-local,
**H** ildevice-homeassistant, **R** rustuya-homeassistant, **M** rustuya-manager.

- [x] **T** 0.3.2: presence remained offline if the old instance stopped after its successor started. Runner

- [x] **T** 0.3.3: choose switch device classes from Tuya categories rather than core's outlet mapping.
- [x] **T/L** Reject a second producer with the same IL prefix/source (tuya2ildevice 0.3.5, rustuya-local 0.0.15).
  `producer_running` probes `<presence>/probe`; a live Runner answers on `<presence>/alive`, causing `AnotherProducer`.
  The daemon exits 1, HA raises `ConfigEntryNotReady` for retry, and the manager tab shows an error and retries every
  30 seconds. Unanswered online presence, such as a Last Will lost with the broker or a pre-0.3.5 producer, only warns.
  Handover now means stopping the old producer before starting the new one.

## Removed functionality

- **HA MQTT discovery (removed 2026-09-24)**: translating IL to HA discovery is unrelated to Tuya and requires HA
  entity rules from ildevice-homeassistant core, creating a distribution dependency. Relays/mirrors require a running
  service, so discovery offered no advantage over ildevice-homeassistant. The code (`discovery/` renderer, publisher,
  operations, CLI `discovery status|clear|restore`, parity tests for 324 fixtures) remains at commit `c646922`.
  If needed again, implement it as a separate IL-consumer tool in ildevice-homeassistant.
